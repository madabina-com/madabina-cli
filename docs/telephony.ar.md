# وحدة إدارة هاتف Asterisk

يضيف Madabina CLI v0.2.2 وصولاً آمناً عبر وكيل عكسي إلى صفحة إدارة Asterisk على `/telephony`. يجب أن يعمل CLI وAsterisk على الجهاز نفسه بنظام Ubuntu أو Debian مع systemd؛ ويمكن لوكيل HTTPS إتاحة الصفحة للمشغّلين عن بُعد. تعرض الأنظمة الأخرى أن الإدارة غير مدعومة. لا تتوفر إدارة جهاز آخر عن بُعد عبر SSH.

## المعلومات والإعدادات

تعرض الصفحة توافق النظام، ووجود Asterisk وإصداره، وحالة خدمة systemd، وتوفر المساعد ذي الصلاحيات. كما تعرض الوحدات المحمّلة ومعلومات للقراءة فقط عن عناوين الشبكة وحالة UFW ونقل/TLS في PJSIP وآخر سجلات Asterisk. تظهر الأدوات غير المتوفرة على أنها غير متاحة.

تغطي النماذج الموجّهة إعدادات PJSIP وامتدادات dialplan وقوائم الانتظار والبريد الصوتي وتحميل الوحدات وبرامج الترميز. تقبل النماذج حقولاً وقِيماً محددة فقط، كما أن تطبيقات dialplan محصورة بقائمة مسموحة. تُحفظ الإعدادات المُدارة في `/etc/asterisk/madabina-managed/` وتُضمّن في ملف الإعداد الرئيسي، مع نسخة احتياطية بامتداد `.madabina-backup`. تُكتب الملفات بشكل ذري ثم يعاد تحميل إعداد Asterisk. عند فشل إعادة التحميل، يستعيد المساعد الملفات السابقة ويحاول إعادة التحميل. تُحفظ كلمات المرور الحالية إذا تُرك حقلها فارغاً؛ أما مصادقة PJSIP الجديدة وصناديق البريد الصوتي الجديدة فتتطلب كلمة مرور.

تتطلب إجراءات تشغيل الخدمة أو إيقافها أو إعادة تشغيلها تأكيداً داخل الصفحة. الشبكة وجدار الحماية وTLS والسجلات للعرض فقط.

## تثبيت المساعد وتشغيله

ثبّت حزمة Debian المطابقة من إصدار رسمي أو مستودع APT. تثبّت الحزمة البرنامج `madabina-telephony-helper` والخدمة `madabina-telephony-helper.service`. يجب تثبيت Asterisk وأن يوفر مجموعة النظام `asterisk`. أضف حساب المستخدم الذي يشغّل `madabina web` إلى المجموعة، ثم فعّل المساعد:

```sh
sudo usermod -aG asterisk "$USER"
sudo systemctl enable --now madabina-telephony-helper.service
```

سجّل الخروج ثم الدخول بعد تعديل المجموعة، وشغّل `madabina web` وافتح الصفحة. افحص المساعد باستخدام `systemctl status madabina-telephony-helper.service`، وافحص Asterisk باستخدام `systemctl status asterisk.service`. تبقى الصفحة للقراءة فقط إذا غاب المساعد أو تعذر على حساب CLI الوصول إلى المقبس.

## الوصول البعيد الآمن عبر HTTPS

للوصول من جهاز آخر، أبقِ CLI مرتبطاً بـ loopback وضع أمامه وكيلاً عكسياً عبر HTTPS يطلب مصادقة المشغّلين. لا تكشف المنفذ 7410 مباشرة على الشبكة المحلية أو الإنترنت. حدّد عنوان HTTPS العام بدقة:

```sh
madabina web --trusted-origin https://pbx.example.com
```

مثال لموقع Caddy (أنشئ بصمة كلمة المرور عبر `caddy hash-password` واستبدل القيمة الوهمية):

```caddyfile
pbx.example.com {
    basic_auth {
        operator REPLACE_WITH_CADDY_PASSWORD_HASH
    }
    reverse_proxy 127.0.0.1:7410
}
```

اضبط جدار الحماية لإبقاء المنفذ 7410 متاحاً على الجهاز فقط، واسمح للعملاء البعيدين بالوصول إلى منفذ HTTPS الخاص بالوكيل حصراً. يجب أن يحافظ الوكيل على ترويسة `Host` القادمة من المتصفح. يقبل `--trusted-origin` عنوان HTTPS واحداً مطابقاً تماماً، ولا يفعّل إدارة الهاتف عند ربط CLI بعنوان LAN. احمِ جميع المسارات بمصادقة الوكيل لأنه يعرض الواجهة كاملة، واختر كلمة مرور قوية وفريدة للمشغّل. يبقى نفق SSH خياراً عند عدم توفر وكيل HTTPS.

## حدود الأمان

يجب أن يستمع خادم الويب على loopback لتفعيل واجهات الهاتف؛ ولا يُقبل الوصول البعيد إلا من عنوان HTTPS واحد محدد عبر --trusted-origin. ربط LAN المباشر لا يتيح إدارة الهاتف.

تتيح عضوية مجموعة `asterisk` إدارة الهاتف على الجهاز؛ أضف المشغلين الموثوقين فقط. يجب أن يصادق وكيل HTTPS على المستخدمين البعيدين وأن يبقي منفذ الواجهة الخلفية خاصاً. راجع التغييرات قبل تطبيقها، واستخدم ملفات `.madabina-backup` للاستعادة اليدوية عند الحاجة. لا يعني إعلان التوافق أن كل توليفة من Asterisk وsystemd والمساعد قد اختُبرت فعلياً.
